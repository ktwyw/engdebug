# Datasets

All files are generated by `python tools/make_datasets.py` with a fixed seed (2026), so they are
reproducible and small enough to commit. Every file begins with `#` comment lines describing it; the
pipeline's loader skips none of them - they are *not* in the CSV files, which start with the header row.

| file | rows | what it is | used by |
|---|---|---|---|
| `clean/sensor_day1.csv` | 1 728 | one day, six sensors on two pumps, every five minutes; clean | reference tests, labs 07-09 |
| `clean/sensor_day2.csv` | 1 728 | the next day: a slow upward drift on T101 and a 30-minute pressure excursion on P101 | labs 07, 08, 10; capstone |
| `clean/large_day.csv` | 51 840 | thirty days: the input for profiling and performance tests | labs 09-10; capstone |
| `clean/calibration.csv` | 11 | a pressure-sensor calibration table (reading vs reference, kPa) | lab 13 |
| `corrupted/sensor_day1_corrupted.csv` | 1 730 | day 1 with every classic fault (table below) | lab 04; reference tests; capstone |
| `corrupted/sensor_missing_column.csv` | 50 | the `unit` column is absent | reference tests |
| `corrupted/sensor_empty.csv` | 0 | header only | reference tests |

The six sensors: `T101`, `T102` temperature (degC); `P101` pressure (bar); `P102` pressure (kPa); `W101`
power (kW); `S102` speed (rpm). Readings are normal noise around a nominal value; the pipeline's
`RANGES` and `DEFAULT_THRESHOLDS` are set around them.

## The faults in `sensor_day1_corrupted.csv`

| row | fault | what it does to a naive parser |
|---|---|---|
| (bytes 1-3) | UTF-8 byte-order mark | the first header becomes `\ufefftimestamp`; `KeyError: 'timestamp'` |
| (every line) | Windows line endings `\r\n` | fine with `newline=""`; stray `\r` in the last field otherwise |
| 1 | header `Reading` capitalised | `KeyError: 'reading'` |
| 19 | reading `N/A` | `ValueError` in `float()` |
| 43 | reading empty | `ValueError` in `float()` |
| 79 | decimal comma `6,958`, unquoted | the row splits into one field too many; reading `6`, unit `958` |
| 102 | blank line | an empty row |
| 122 | timestamp `2026-03-02T...` (ISO `T` separator) | `ValueError` in `strptime` |
| 152-153 | a duplicated row | double counting; "timestamps not strictly increasing" |
| 200 | reading `9999.0` on T101 | an impossible temperature that passes every type check |
| 262 | unit `degF` | `KeyError` in the limits table |

Row numbers count the header as row 1, as the loader reports them.
